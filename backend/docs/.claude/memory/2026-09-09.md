## 3. Repository 层（src/）
约定（与用户确认）：共享 `db.js` + 所有仓储方法接受**可选 connection 参数**，以便跨仓储单事务；预处理语句防注入；中文 JSDoc；ES Module。

### src/db.js
- `resolveDbPath()`：优先 `process.env.DATABASE_PATH`（相对路径以 backend 根为基准），默认 `backend/database.db`。
- `getConnection(dbPath?)`：每次打开新连接并 `PRAGMA foreign_keys = ON`、`busy_timeout = 5000`（注：导出名中途由 `openConnection` 统一为 `getConnection`）。
- `withDb(connection, fn)`：传入连接则复用（事务内），否则自开自关。
- `withTransaction(fn, { immediate })`：`BEGIN` / `BEGIN IMMEDIATE`，成功提交、失败回滚。

### 七个仓储（src/repositories/，均通过临时独立库冒烟断言）
1. `staffWhitelistRepository.js`：`findByName`（按名查 → `{id,name}|null`）、`insertMany`（`INSERT OR IGNORE`，返回实际插入行数）。
2. `eventRepository.js`：`findById`、`findBySlug`、`getCurrentEvent`（最新 active，`ORDER BY id DESC`）、`isActive`（纯函数：active 且未到 end_at）、`isActiveById`。
3. `badgeRepository.js`：`findByEventIdAndCode`（查 knowitall）、`findById`、`listByEventId`。
4. `boothViewRepository.js`：`upsert`（同一设备/活动/摊位只刷 `last_viewed_at`+`view_count+1`）、`countDistinctBooths`（去重摊位计数）。
5. `userBadgeRepository.js`：`unlock`（幂等 `ON CONFLICT DO NOTHING`，返回是否首次）、`isUnlocked`、`listByDeviceAndEvent`（join badges 做活动隔离）。
6. `claimTokenRepository.js`：`insertIgnore`（按 device 幂等首签，冲突保留原码）、`findByDeviceId`、`findByTokenHash`、`markRedeemed`（条件更新 `status='active'`→`redeemed`，并发只成功一次）。
7. `redemptionRepository.js`：`insert`（append-only 核销记录，`UNIQUE(claim_token_id)`；须与 `markRedeemed` 同事务）。

关键业务规则依据 `docs/BACKEND_PLAN.md`（§7 表设计 / §8 徽章解锁事务 / §10 核销 / §11 并发 / §13 事务）。

## 4. Service 层（src/services/，均临时库冒烟通过）
- `authService.js`：studentLogin / staffLogin / verifyToken / getCurrentUser；依赖 jsonwebtoken；JWT exp=活动截止秒；staff 每次实时复查白名单（撤销即失效）；错误 message=API 错误码。
- `boothViewService.js`：recordView 在 `withTransaction` 内完成 upsert→去重计数→knowitall 阈值→幂等 unlock→isUnlocked，返回 `{eventId, boothId, uniqueBoothCount, badges}`（boothId 为验证时发现并修复）；getProgress 只读。
- `claimTokenService.js`：getRewardStatus / getClaimToken / getClaimTokenStatus，另导出 generateClaimToken（`XXXX-XXXX-XXXX-XXXX`，字符集去 0/O/1/I/L）与 hashToken（SHA-256）；claimStatus 优先级 redeemed > expired > active > none。
  - 备注①：`uniqueBoothCount` 需 boothViewRepository.countDistinctBooths（用户依赖清单漏列，已补）。
  - 备注②：本阶段无加密密钥，领取码明文暂存 `token_ciphertext` 占位以支持“复用返回同一码”；哈希列用于查码/核销。接服务端加密时替换存取两端即可，仓储接口不变。
- `staffRedemptionService.js`：redeem 用 `BEGIN IMMEDIATE`，markRedeemed（`WHERE status='active'` 条件更新，false=被抢先）与 redemptions.insert 同事务原子完成。
- package.json：`type: module`、engines node>=22.5；依赖 jsonwebtoken、express。

## 5. HTTP 层（src/middleware + src/routes，逐个真实 HTTP 冒烟通过）
- `middleware/requireAuth.js`：requireAuth / requireStaff，共享 `attachUser`。token 缺失/无效/过期 → AUTH_REQUIRED；staff 被撤销 → INVALID_TOKEN；非 staff → STAFF_REQUIRED。
